# Bixant design system

Design tokens, theming and the `bx-*` web components built on them: fluid, contrast-checked tokens and themes, defined as JSON and compiled to CSS custom properties. Every component takes its look from those tokens and exposes its whole appearance as its own CSS variables.

## How to use this Storybook

- **Toolbar**: switch **theme** (light, dark, and the example custom themes) and **`--bx-scale`** (0.85–1.5).
- **Foundation / Tokens**: palettes, per-theme roles, semantic colors, spacing, radius, elevation, typography.
- **Foundation / Contrast**: WCAG contrast of every documented token pair for the selected theme (the same data the build enforces).
- **Theming / Playground**: runtime theming from seed colors, with generated CSS.
- **Theming / Component variables**: complete skins built only from component CSS variables, side by side with the defaults, plus a single-element override.
- **Core, Data table, Data list**: one entry per component with every variant, state and size, live controls, and keyboard/accessibility usage.

## Customizing a component with CSS variables

Every themeable surface is a documented custom property named `--bx-<component>-[<part>-][<state>-]<property>` (for example `--bx-input-radius`, `--bx-tab-selected-fg`, `--bx-dialog-backdrop-bg`). Each defaults to a token, so unset variables keep following the theme. Set them on a wrapper to restyle everything inside it, or on one element to restyle just that one:

```css
.checkout {
  --bx-button-radius: 0;
  --bx-input-border-color: var(--bx-border-strong);
  --bx-dialog-shadow: none;
}
```

A component's variables are listed in its docs page (generated from the source) and in the feature docs under `docs/features`. Rules, naming and how this is enforced: `docs/design-system/component-guidelines.md` → Styling API.

## Principles (in priority order)

1. Accessible by default
2. Adapts to its space (container, not viewport)
3. Correct at scale
4. Tokens, not values
5. One way to do it
6. Themeable, not forkable
7. Native first
8. Small and predictable

Full documentation lives in the repository under `docs/design-system` (principles, foundations, theming, governance).

## Design tokens for Figma

`@bixant/design-system/tokens.dtcg.json` exports all tokens in the Design Tokens Community Group format, organized as `foundation`, `light` and `dark` sets, ready for Tokens Studio or a Figma variables importer. `tokens.figma.json` has the fluid dimensions evaluated to pixels.
